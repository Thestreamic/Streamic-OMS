Strawberry and Avid Media Composer: Setting Up a Collaborative Post-Production Workflow

Strawberry from Production Flow is one of the most capable PAM (Production Asset Management) systems available for small and mid-size post facilities. Paired with Avid Media Composer, it provides a lightweight alternative to full MAM infrastructure at a fraction of the cost.

By The Streamic Editorial Team · March 2026 · 10 min read

What Is Strawberry?

Strawberry is a browser-based PAM designed for multi-editor post-production environments. It manages project assets, tracks versions, controls access to shared storage, and automates ingest and delivery. Unlike enterprise MAM systems, Strawberry runs on a standard Linux or macOS server and requires no specialised hardware.

Key capabilities relevant to Avid workflows include: hot folder ingest with automatic proxy generation, project-level access control, Avid bin sharing via shared storage, and automated delivery packages.

Architecture Overview

A typical Strawberry + Avid deployment looks like this:

  • Shared storage: NAS (Synology, QNAP, or any SMB/NFS share) — all Avid workstations and the Strawberry server point to the same volumes
  • Strawberry server: Ubuntu 22.04 LTS or macOS, connected to shared storage
  • Avid workstations: Map shared storage as Avid MediaFiles-compatible paths
  • Proxy tier: Strawberry generates H.264 proxies; high-res media lives on the NAS

Step 1: Install and Configure Strawberry

  1. Download the Strawberry installer from the Production Flow website. A 30-day trial licence covers a full installation.
  2. Run the installer on your server. The setup wizard configures the Strawberry database (PostgreSQL) and web server automatically.
  3. Access the Strawberry web interface at http://server-ip:8080 and complete the initial setup:
    • Set the media root to your NAS mount point: e.g. /mnt/nas/media
    • Set the proxy output path: /mnt/nas/proxies
    • Configure your SMTP server for notification emails

Step 2: Configure Shared Storage for Avid

Avid Media Composer requires media to be stored in a specific folder structure for it to appear in bins. Strawberry must be configured to write to an Avid-compatible path.

  1. On your NAS, create the folder structure: \\nas01\MediaFiles\MXF\1
  2. In Strawberry's Admin panel, set the Avid MediaFiles path to match this location.
  3. On each Avid workstation, map the NAS share and confirm Media Composer can see the MediaFiles folder via Media Tool.
  4. Enable AMA (Avid Media Access) linking in Media Composer preferences so editors can link to files directly without copying.
Performance note: For smooth multi-user Avid editing over a NAS, ensure your network is 10GbE minimum. 1GbE is insufficient for multiple simultaneous DNxHD streams. Avid's ISIS/NEXIS shared storage handles this natively, but a well-configured 10GbE NAS works well for small teams.

Step 3: Set Up the Ingest Hot Folder in Strawberry

  1. In Strawberry's web interface, go to Settings → Hot Folders.
  2. Add a new hot folder pointing to: /mnt/nas/ingest
  3. Configure the ingest profile:
    • Accepted formats: MXF, MOV, MP4, AVI — Strawberry will process any file dropped here
    • Generate proxy: Yes — H.264 1280×720 for review
    • Transcode to Avid: DNxHD 115 (or DNxHR for 4K) for editing-grade media
    • Output to Avid MediaFiles path: Yes
  4. Save and activate the hot folder.

Step 4: Create a Project and Assign Editors

  1. In Strawberry, create a new Project (e.g. News Programme S01).
  2. Add your Avid editors as users and assign them to the project with appropriate permissions (Editor, Viewer, Admin).
  3. In the project, create Bins that mirror your Avid bin structure — this provides the organisational layer that Avid itself lacks for multi-user environments.
  4. Assign ingested assets to the relevant project bin in Strawberry. Editors opening Media Composer will find the same assets in their Avid bins via the shared MediaFiles path.

Step 5: Version Control and Review

One of Strawberry's strongest features is version management — something Avid's native toolset handles poorly outside of full Interplay/MediaCentral deployments.

  1. When an editor exports a cut from Avid, drop it into the Strawberry Review hot folder.
  2. Strawberry generates a proxy and creates a new version entry in the project timeline.
  3. Reviewers access the version via Strawberry's browser-based player — no Avid licence required for review-and-approval.
  4. Approved versions are flagged in Strawberry and can trigger an automated delivery action.

Step 6: Automated Delivery from Strawberry

  1. In Strawberry, go to Settings → Delivery Profiles.
  2. Create a delivery profile named Broadcast_Master:
    • Source: Approved project asset
    • Transcode: MXF OP1a, DNxHD 185, 48kHz PCM audio (standard broadcast delivery spec)
    • Destination: \\nas01\delivery\broadcast
  3. Attach this profile to your project. When an asset is approved, Strawberry triggers the transcode and delivery automatically — no manual export required from Avid.
AdSense tip: Strawberry's browser-based review workflow eliminates the need for editors and clients to have Avid licences for review and approval, significantly reducing per-seat costs for production companies that bill per project.

Common Issues and Fixes

  • Avid cannot see Strawberry-ingested media: Check the msmFMID.pmr file in the MediaFiles folder — Avid uses this for media indexing. If it is locked or corrupted, Media Composer cannot enumerate the media. Restart the Avid Interplay Engine or simply delete and allow Avid to regenerate it.
  • Proxy generation fails: Ensure FFmpeg is installed on the Strawberry server and accessible in the system PATH. Strawberry uses FFmpeg for proxy generation.
  • Permissions errors on NAS: Strawberry's service user and all Avid workstation user accounts must have read/write access to the same NAS shares. On Synology NAS, create a dedicated shared folder with a group that includes all relevant users.
