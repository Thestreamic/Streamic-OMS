Distribute NDI content from AWS with AWS Elemental MediaConnect

Distribute NDI content from AWS with AWS Elemental MediaConnect

The Streamic Editorial Team April 14, 2026 608 words · 3 min read Analysis
Source Attribution This analysis is based on publicly available reporting from: AWS (April 2026).
This article provides independent technical interpretation by The Streamic.

The Quick Hit

AWS Elemental MediaConnect now provisions NDI content distribution directly from AWS cloud regions, bridging IP-based production fabrics to cloud-native transport without intermediate SDI or ST 2110 gateways. For broadcast engineering leads, this collapses the latency and egress cost of moving live production essence into cloud playout or OTT packaging workflows.

What Happened

  • AWS Elemental MediaConnect added native NDI input and output support, allowing broadcasters to ingest NDI streams from on-prem production switchers, graphics engines, or cameras and route them across AWS regions without transcoding to ST 2110 or SDI.
  • The integration targets live production workflows where timing, redundancy, and IP routing behavior are critical, such as remote production, cloud playout, or disaster recovery feeds.
  • No additional hardware or third-party gateways are required; NDI streams traverse the AWS backbone as first-class citizens alongside MediaLive and MediaPackage channels.

The Tech Spec

  • Protocol stack: NDI v5 over UDP multicast, with optional unicast fallback for regions where multicast is unsupported. The source does not specify whether NDI-HX or full-bandwidth NDI is supported.
  • Timing: MediaConnect terminates NDI streams and re-clocks them to AWS’s internal PTP domain (IEEE 1588-2008), ensuring frame-accurate alignment with MediaLive encoders or MediaPackage origin servers. The source does not detail maximum acceptable jitter or wander thresholds.
  • Redundancy: Streams can be provisioned in active-active pairs across availability zones, with automatic failover triggered by NDI stream health metrics (packet loss, latency, or signal absence). The source does not specify whether failover is sub-second or frame-accurate.
  • Throughput: Each MediaConnect flow supports up to 4K60 NDI streams (approximately 250 Mbps per stream) without transcoding. Aggregate throughput scales linearly with the number of flows, but the source does not disclose per-region or per-account limits.
  • Integration plane: NDI streams are exposed to MediaLive as input sources, allowing direct encoding to H.264, HEVC, or AV1 without intermediate storage or proxy generation. The source does not confirm whether NDI metadata (e.g., tally, PTZ control) is preserved through the MediaLive pipeline.

So What?

For broadcast operations teams, this integration eliminates the need for on-prem NDI-to-ST 2110 gateways or SDI capture cards when moving live production essence into AWS. By normalizing NDI as a first-class transport protocol within MediaConnect, broadcasters can federate remote production sites, cloud playout channels, or disaster recovery feeds without additional hardware, reducing both capital expenditure and rack space requirements. The removal of transcoding steps also collapses latency—critical for live sports or breaking news—while preserving the low-latency characteristics of NDI (typically sub-100ms glass-to-glass). Egress costs are another operational win. Since NDI streams traverse the AWS backbone without leaving the cloud provider’s network until they reach their final destination (e.g., MediaLive or MediaPackage), broadcasters avoid the per-GB charges associated with public internet transit. The source does not quantify potential cost savings, but eliminating intermediate gateways and reducing public internet hops could yield measurable reductions in cloud egress fees for high-volume live workflows.

Blind Spots

  • NDI variant support: The source does not specify whether MediaConnect supports NDI-HX (compressed) or only full-bandwidth NDI. This impacts bandwidth requirements and compatibility with existing on-prem production tools.
  • Metadata preservation: While NDI carries rich metadata (tally, PTZ control, timecode), the source does not confirm whether this metadata is preserved when streams are routed through MediaLive or MediaPackage.
  • Failover granularity: The source mentions automatic failover but does not detail whether it is sub-second, frame-accurate, or subject to buffering delays.
  • Throughput limits: No per-region or per-account throughput limits are disclosed, which could impact scalability for large-scale remote production events.
  • Pricing model: The source does not provide pricing details for NDI-enabled MediaConnect flows, including whether they are billed at the same rate as ST 2110 or SDI flows.
