How to Build a Vantage Transcode Workflow: Any File to MP4 on a Local NAS Share

Telestream Vantage is the industry standard for automated media processing. This guide builds a production-ready hot folder workflow that ingests any file format and delivers H.264 MP4 to a local NAS.

By The Streamic Editorial Team · March 2026 · 10 min read

What You'll Need

  • Vantage 8.x or later with Transcode and Workflow Designer licences
  • Vantage Management Console access
  • A NAS share mounted and accessible as a UNC path (e.g. \\nas01\media\ingest)
  • Vantage service account with read/write access to both source and destination shares

Step 1: Create the Source Hot Folder

  1. Open Vantage Management Console → Storage.
  2. Click Add to create a new storage location.
  3. Name it NAS_Ingest and set the UNC path: \\nas01\media\ingest
  4. Set the Vantage service account as the access credential. Test the connection.
  5. Repeat to create a second storage location named NAS_MP4_Output pointing to \\nas01\media\output\mp4
Best practice: Never use mapped drive letters (Z:\) in Vantage. Always use UNC paths. Vantage services run as background processes and may not have access to user-mapped drives.

Step 2: Build the Workflow in Workflow Designer

Open Vantage Workflow Designer and create a new workflow.

2a. Add a Watch action

  1. Drag a Watch action from the palette onto the canvas.
  2. Double-click to configure. Set Hot folder to NAS_Ingest.
  3. Set File filter to *.* to accept any input format.
  4. Enable Trigger on stable file and set stability to 5 seconds. This prevents Vantage processing files still being written to the share.
  5. Set Polling interval to 30 seconds for production workloads.

2b. Add a Transcode action

  1. Drag a Transcode action and connect it to the Watch action output.
  2. Double-click to open the encoder configuration.
  3. Click New Configuration and name it MP4_H264_Broadcast.
  4. Set the following parameters:
    • Container: MP4
    • Video codec: H.264 (x264 or MainConcept H.264)
    • Profile: High, Level 4.1
    • Bitrate: CBR 8 Mbps (adjust for your delivery spec)
    • Resolution: Same as source (use Auto)
    • Frame rate: Same as source
    • Audio codec: AAC-LC, 320 kbps, 48 kHz, stereo
  5. Under Output, set the destination to NAS_MP4_Output.
  6. Set the filename pattern: {OriginalFilename}_MP4.mp4 — this preserves the source filename.

2c. Add a Notify action (optional but recommended)

  1. Add an Email or Message action at the end of the chain.
  2. Configure it to send a completion notification to your operations team, including the output file path and job duration.

Step 3: Configure Error Handling

In the Transcode action properties, click the Errors tab:

  • Set On failure: Retry 3 times with 60-second delay
  • After all retries fail: Move source file to \\nas01\media\failed and send alert email
  • Enable Save detailed job log for troubleshooting
Important: Always configure a failure path. Without it, failed jobs silently pile up in the queue and can stall subsequent jobs when Vantage hits its concurrent job limit.

Step 4: Activate and Test the Workflow

  1. Right-click your workflow in the Workflow Designer and select Activate.
  2. Drop a test file (any format — MXF, MOV, MP4, AVI) into the NAS_Ingest hot folder.
  3. In Vantage Job Status, confirm the job appears and transitions: Waiting → Processing → Complete.
  4. Check the output folder for the _MP4.mp4 file.
  5. Validate the output using MediaInfo or VLC to confirm codec, bitrate, and audio layout.

Step 5: Performance Tuning

  • Parallel jobs: In Vantage Management Console → Services, set the Transcode service to allow 2–4 concurrent jobs depending on your server CPU.
  • Priority routing: If you have multiple Vantage nodes, configure the workflow to use the node with the highest available resource headroom.
  • MediaInfo validation: Add a Metadata action after the Transcode to extract QC metadata and log it to your MAM or a CSV report.
Broadcast tip: For news and live event workflows, lower the hot folder polling interval to 5 seconds and enable Immediate trigger on file arrival instead of stability checking. Accept the small risk of partial-file processing in exchange for faster turnaround.
